# TimeTrak 自动同步（独立手表计时模型）

## 同步拓扑

- **手表是独立的时间记录设备**：开始、停止时间先保存到手表持久化 SQLite，不需要手机连接。
- **局域网传记录，不传控制命令**：手表将已完成记录（record_id、activity_id、started_at、ended_at、comment）经手机热点或同 Wi-Fi 上传到手机 `POST /v1/import`。手机原生 Room 写入后回 ACK；手表据此将记录标记已接收。丢 ACK 重试仍以 UUID 幂等导入。
- **手机自动上传云端**：已有 NativeCloudBridge 检查原生 Room 变更并同步到云端；导入完成后主动唤醒。断网时由手机 Room + 云 outbox 持久化等待。
- **独立云模式**：手表原有 CloudStore 模式独立存在，使用 HTTPS 直接上传云端，不等同于上述 Watch LAN 本地记录。
- **活动目录**：先从手机获取一次活动列表并缓存到手表。手表断网后仍能使用已经缓存的活动，尚未同步的新活动需下次联网下载。

## 自动触发

- 手表 LAN：记录写入本地后不等待网络；约2秒尝试局域网同步、记录完成主动触发一次，另由系统后台任务按系统允许时机尝试。
- 手机 Room：正常应用进程运行时约2秒扫描，也被记录变更事件主动唤醒；后台网络任务定期补传，不需要打开上传页面。
- 手表云模式：写入 CloudStore outbox 后触发原有自动上传任务。
- 使用 Android JobScheduler，不依赖 Google Play 服务。Android 电池策略、Doze、后台限制、手动强制停止会影响触发时间；15分钟是系统后台周期调度的最低配置值，不是实时 SLA。

## 明确不提供的功能

- 手表不是遥控手机：不存在“Watch 按开始，命令手机开始计时”的接口。
- 目前手机局域网 HTTP 接收服务仍是**前台 Activity**，页面退出时停止监听；手表保留记录，等重新连通再上传。
- 目前 LAN 模式仅同步已经结束的计时会话，不实时复制未结束的计时状态。
- 手机进入后台、手机热点切换、手表联网并不保证每秒都能同步。
- 局域网 HTTP 未加密，只可在可信个人网络使用；切勿开放公网。

## 必须用真实数据验证

1. 首次在线缓存活动，断网开始并停止计时，手表重新打开仍能看到完整历史及待上传。
2. 手机恢复局域网服务后无需按上传按钮，记录从 Watch SQLite 进入手机原有 Room。
3. 同一 UUID 重发至少两次，手机仅新增一条。
4. 手机云端真正 ACK，记录出现在云端，手机保留同步失败的本地变更。
5. 手机锁屏/手表断网/应用进程被系统重启后，各自数据不丢；不能将 GitHub CI 构建通过视作真机验收。

详见 `docs/WATCH5_DIRECT_WIFI.md`。
