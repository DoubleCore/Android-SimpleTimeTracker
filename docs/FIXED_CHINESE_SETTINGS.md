# TimeTrak：设置集中化与中文活动/标签内置（2026-10-23）

## 已实现

- 原版手机主界面顶部不再出现「云同步连接设置」横幅。
- 原版手机的「设置」页增加「TimeTrak · 同步与功能设置」入口。
- 新增功能的设置和状态说明统一位于 `CloudSettingsActivity`：
  - 云端 URL、私有 Bearer 密钥的保存；
  - 查看同步状态及失败操作；
  - 语音描述、局域网同步、AI 分类的功能边界说明；
  - 查看内置中文活动清单（只读）。
- 通用云计时界面移除「创建活动」输入框与内嵌连接参数；计时页面仅显示计时、同步状态和历史。
- 手机端在**没有配置服务器时**也会自动初始化内置活动及标签，避免首次使用时还需要编辑标签。
- 手表/通用云计时数据使用同一组固定活动名称与确定性 UUID，使用 `put_activity` 幂等同步；相同活动不会因两端初始化而产生两套 UUID。
- 新增本地数据库仪器测试：固定 UUID、二次初始化不重复排队、重新打开数据库不重复排队。

## 内置的活动与标签

活动（12 个）：深度学习、科研工作、编程开发、课程学习、阅读、写作整理、会议交流、日常事务、运动、休息、生活、睡眠。

手机本地标签（8 个）：计划、专注、资料整理、深度工作、协作沟通、复盘、中断、临时事务。

**代码唯一维护位置：**
- 活动：`cloud_sync/src/main/java/org/doublecore/stt/cloud/FixedActivities.java`
- 手机标签：`NativeCloudBridge.ensureFixedTags()`

修改活动名称会影响新构建的确定性活动 UUID，因此后续要调整名字应设计显式迁移，不能直接改动在线工作区的已有 UUID。

## 数据兼容性与边界

1. **不会删除**原有活动、标签、历史计时、统计、待同步记录和云端数据。
2. 内置活动不提供新开发的增删/重命名配置页；但是原版 STT 自带的历史活动与标签编辑页面目前仍保留，因此这里的“固定”指**默认清单写死、自动初始化、无需配置**，不是数据库层全面禁止用户修改。未来若要求完全禁止修改，需处理原版编辑入口及历史数据迁移。
3. 手机原版 STT 与云服务同步仍受服务器兼容协议约束；本改动不解决 `native_records_v1` 的部署版本匹配。
4. 手机本地标签目前不进行云端/手表同步；手表只使用固定中文活动，暂无标签编辑器。
5. 语音描述：手机复用已有系统语音识别入口；手表语音备注尚未实现。
6. 局域网：独立 M0 探针验证不等于当前完整版 LAN 后台服务上线。
7. AI 自动分类：**尚未接入模型 API**。不能显示虚假的“已分类”状态或让用户填写暂时无效的 API 参数。
8. 自动上传仍受到 Android 后台限制；切勿承诺应用进程被系统杀掉后仍可实时同步。
9. 服务器密钥没有被硬编码进仓库；已有的私有构建资产配置仍可用。

## 构建/验收

- 手机和手表 APK：`bash ./gradlew :app:assembleBaseDebug :wear:assembleDebug --no-daemon`
- 运行通用云端 APK Android 仪器测试：`bash ./gradlew -p tools/cloud-app :app:connectedDebugAndroidTest --no-daemon`（需模拟器）
- 真机检查：新安装手机端离线可出现固定中文活动与标签；设置入口可访问；Watch 5 连接同一服务器后出现同名活动；往返/重启不重复初始化；原有计时历史完整；原本已经结束的计时保持结束状态。
- 这次代码写入 GitHub 不代表上述编译/真机验收已经执行。
