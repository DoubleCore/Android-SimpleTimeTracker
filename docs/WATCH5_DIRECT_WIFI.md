# Watch 5 独立计时 → 手机 Wi-Fi 自动接收 → 手机 HTTPS 云同步

## 唯一正确的数据方向

**Watch 5 是独立计时器，不是手机遥控器。**

1. 手机把可用活动目录发给手表；手表保存在自己的 SQLite 缓存中。
2. 在手表选择活动并点击开始：**只在手表 SQLite 写入开始时间**，即使手机不在场也成功。
3. 在手表点击停止：**先在手表 SQLite 写入结束时间**，形成待同步的完整时间记录。
4. 手表经 Wi-Fi/手机热点尝试 POST `/v1/import` 上传完整记录，稳定 UUID + 原始时间戳；手机只负责导入，不执行远程开始/停止计时。
5. 手机原版 Room 确实写入该记录后，返回 ACK；手表收到匹配 UUID 回执后将本地记录标记已同步。重复发送同一 UUID 不产生重复记录。
6. 手机现有 `NativeCloudBridge` 监听变更，把新记录加入待上传队列，经 HTTPS 发到已有云端。

## 行为边界

- 手表**独立开始/停止，无需手机在线**。手表在失去 Wi-Fi 时依旧存储所有计时，并在可达时自动补传已完成的记录。
- 当前 LAN 模式只传**已完成的记录**：手表正在进行的计时仍属于手表本机，手机不会实时显示它为手机端正在计时，也不会控制它。手机收到记录时保留手表原始起止时间。
- 首次需要手机提供活动目录；已有缓存之后手表可以离线使用这些活动。
- 与云直连模式并存：手表旧云模式有独立的 CloudStore 队列，不与手表 LAN 本地记录数据库混写；手表原有云上传任务仍保留。
- 当前**手机 LAN 接收服务在 Activity onStop 后停止**。手表仍能计时、仍留有未上传记录；手机接收服务下一次可达时，手表重试上传。
- 手机必须先配置并运行兼容 `native_records_v1` 的 HTTPS 云端服务，才能确认真正上传云端。手机 Room 保存和云端 ACK 是两个不同状态。
- Watch SQLite 使用 noBackup 目录，卸载清除应用数据将删除尚未上传的时间记录。升级安装请先确认包名/签名兼容并备份。
- LAN 是带配对令牌的**未加密 HTTP**，仅在本人可信路由器/热点使用，不可公网端口映射。

## 安装与使用

- 构建 APK：`bash ./gradlew :app:assembleBaseDebug :wear:assembleDebug --no-daemon`
- 手机运行新 APK，打开“Wi-Fi直连手表（手机服务端）”，选择手机热点或局域网 IPv4，启动 8765 服务；记录手机 IP 和32位配对密钥。
- 手表 Wi-Fi 连到相同网络，进入“Wi-Fi直连手机”填 IP 和配对密钥。连接后手机活动列表缓存到手表。
- 以后直接在手表点击开始/停止（**不要求手机持续在身边**）；手表自动上传完成记录。点击“Wi-Fi直连设置”可查看待传条数。
- 手机在原版顶部“云同步”设置兼容 HTTPS 服务端。手机接收到手表记录后，自动通过已有桥接器上传云端。
- Android 原生 JobScheduler 在允许的系统时机尝试后台补传；15 分钟是最低周期设置而非精确实时保证。

- [ ] 手机云同步完成后，服务器相同会话仅一条，手机与云端历史一致
