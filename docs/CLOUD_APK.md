## 中文活动与标签
- 原版默认示例的真正来源：`GetDefaultRecordTypesInteractor.kt`，原先直接写了 `Games/Tv/Work` 等 18 个英文名称。
- 现替换为 12 个写死的中文默认活动，仍使用原有活动卡片组件和原版内置图标、配色。
- `NativeCloudBridge.initializeChineseCatalog()` 在手机启动时无须连接云服务即可运行一次：新数据库插入上述 12 个活动和 8 个中文标签。
- 已有数据库仅转换名字和图标都完全匹配的原版内置英文预设；使用 `UPDATE recordTypes SET name=...`，**不执行 REPLACE/DELETE**，以保持历史记录与关联不变。
- 不清空用户自行创建的中文/英文活动；不重复生成活动。已保存一次性标记后，用户未来手动删除活动不会被强制补回。
- 标签目前只在手机本地，不承诺它们会跨端同步或被 AI 自动分类。

## 手机与手表同步：实现边界

### 已实现的是云端中转（有条件可用）
1. 手机原版 Room 数据库 `NativeCloudBridge` -> 本地 `CloudStore` 持久 outbox。
2. 手机和国行 Watch 5 分别通过 HTTPS 访问同一云服务器；无需 GMS。
3. 手表 `WearDataRepo` 的开始/停止先写本地队列，由 `CloudSync` 上传。
4. 服务端若正确部署并支持 `native_records_v1`，双方能拉取活动与会话、手机能把手表记录导入原版数据库。
5. 后台同步大约每 2 秒尝试一次；不保证系统杀进程后仍立即同步。双真机端到端尚未由本构建的 CI 证明。

### 尚未实现的是 Wi-Fi 直连（不是只有未设置）
- 目前仅有独立的 `tools/lan-probe` 健康检查测试程序；它的 `ProbeServer` 明确只接受带令牌的 `GET /health`，不处理活动或记录。
- 正式 APK 中没有手机常驻 LAN 业务 HTTP 服务，没有手表的 LAN 数据推送/差量拉取，以及云断开时的本地双向事件合并。因此 **不能宣称手表已经直接通过局域网把计时数据传给手机**。
- 落地 Wi-Fi 直连需要把持久 outbox 协议（活动、开始/停止、会话修改、ACK、游标、冲突恢复）接入手机 LAN 服务，并让手表优先 LAN、断网缓存、云端备份可选。不能用“LAN 检测成功”代替数据同步验收。
- 现有 `CloudHttp.normalize` 只允许 `https` URL；因此直接填 `http://192.168.x.x` 也不是可用的 LAN 同步方案。
